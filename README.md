# 웹 기반 병원 관리 시스템 (Web-based Hospital Management System)

Node.js(Express), MongoDB, Pug/HTML을 활용해 병원 등록·승인, 역할 기반 접근 제어, 병실 관리, 진료 예약, 환자 차트 관리, 백업 기능을 하나의 웹 플랫폼으로 통합한 병원 관리 시스템 프로젝트입니다.  
2025년 3학년 1학기 `웹 서버 프로그래밍` 강의 팀 프로젝트로 진행했으며, 세션 기반 인증, 권한 분기, 데이터 모델링, 서버-뷰 연동 구조를 함께 다뤘습니다.

> 이 저장소는 2025년 3학년 1학기 과제물을 바탕으로,  
> 당시 로컬 환경에 보관하던 소스코드를 **포트폴리오 및 코드 아카이브 목적**으로  
> 개인 GitHub 저장소에 옮겨 정리한 버전입니다.  
> 원 프로젝트는 Git 기반 협업으로 진행되지 않았으며, 팀원별로 분담 개발 후 최종 통합하는 방식으로 마무리했습니다.

## 2. 기술 스택

- **개발 언어**: JavaScript (Node.js, ES6+)
- **운영체제 환경**: Windows 10 / 11
- **개발 도구**: Visual Studio Code
- **서버 및 프레임워크**: Node.js, Express.js
- **데이터베이스**: MongoDB, Mongoose
- **프론트엔드 및 UI**: Pug, HTML5, CSS3, HTML5 Canvas, FullCalendar
- **주요 라이브러리**
  - **Backend**: `express`, `mongoose`, `express-session`, `bcrypt`, `nodemailer`, `dotenv`, `morgan`, `cors`
  - **Frontend**: `FullCalendar`, `HTML5 Canvas API`

## 3. 실행 방법

### 1) 실행 전 준비

- 로컬 MongoDB 실행 환경이 필요합니다.
- 프로젝트 루트에 `.env` 파일을 생성해 환경변수를 설정합니다.
- 메일 인증 기능을 사용하려면 이메일 계정 정보가 필요합니다.
- 문자 발송 관련 항목은 연동 테스트 용도로 포함되어 있으며, 실제 서비스 수준으로 완성된 기능은 아닙니다.

### 2) 환경 변수 설정

```env
SESSION_SECRET=your_session_secret_key
NODE_ENV=development

MONGO_URL=mongodb://localhost:27017
DB_NAME=hospital_db

EMAIL_USER=your_email@gmail.com
EMAIL_PASS=your_gmail_app_password

TWILIO_SID=your_twilio_account_sid
TWILIO_AUTH_TOKEN=your_twilio_auth_token
TWILIO_PHONE_NUMBER=your_twilio_phone_number
```

### 3) 설치 및 실행

```bash
npm install
npm start
```

### 4) 실행 후 확인

- 기본 실행 주소: `http://localhost:3000`
- 회원가입 및 로그인 후 역할에 따라 접근 가능한 메뉴가 달라집니다.
- 병원 등록/승인, 병실 관리, 예약 관리, 차트 관리 기능을 순서대로 확인할 수 있습니다.

## 4. 시스템 아키텍처 및 핵심 포인트

### 시스템 아키텍처

```text
[Client]
   ↓
[Express Router]
   ↓
[Session / Role Middleware]
   ↓
[Controller]
   ↓
[Mongoose Model]
   ↓
[MongoDB]
   ↓
[Pug View / JSON Response]
```

### 핵심 포인트

- **세션 기반 인증과 역할 분기**
  - 로그인 여부와 사용자 역할에 따라 접근 가능한 기능을 구분
  - 서버 관리자, 병원 관리자, 의료진, 환자 흐름을 나누어 처리

- **승인 절차가 포함된 병원 관리 흐름**
  - 가입 후 즉시 모든 기능을 사용하는 구조가 아니라, 승인 단계를 거쳐 권한이 활성화되도록 구성
  - 병원 도메인 특성을 반영해 관리 프로세스를 설계

- **병실 상태 시각화**
  - 병실 데이터를 Canvas 기반 화면으로 표시
  - 병상 수와 입원 현황에 따라 상태를 구분해 볼 수 있도록 구현

- **예약 및 차트 관리 기능**
  - 의료진 일정 등록과 환자 예약 흐름을 연결
  - 환자 정보와 진료 기록을 데이터베이스에 저장하고 관리할 수 있도록 구성

### 주요 디렉토리 및 파일

- `app.js`
  - Express 앱 초기 설정
  - 미들웨어, 세션, 라우터 연결 담당

- `routes/`
  - 인증, 관리자, 병실, 예약, 환자 관련 요청 경로 정의

- `controllers/`
  - 요청 처리 로직 및 기능별 비즈니스 로직 담당

- `models/`
  - 사용자, 병원, 병실, 환자, 일정 등 Mongoose 스키마 정의

- `views/`, `public/`
  - Pug 템플릿과 정적 리소스 관리

- `utils/backup.js`
  - 데이터 백업 관련 유틸리티

## 7. 트러블 슈팅

### 1) 렌더링 방식 혼용으로 인한 구조 혼선
초기에는 Pug 템플릿과 정적 HTML이 함께 사용되면서 화면 구성 기준이 다소 섞여 있었습니다.  
라우팅 경로와 정적 파일 제공 구조를 정리해 두 방식이 충돌하지 않도록 조정했습니다.

### 2) 모듈 통합 시 데이터 형식 불일치
팀원별로 나눠 개발한 기능을 합치는 과정에서 변수명, 요청/응답 형식, 식별자 처리 방식이 달라 통합 작업에 시간이 걸렸습니다.  
최종 단계에서 네이밍과 입출력 형식을 맞추고 라우트 구조를 정리해 모듈 간 연결을 안정화했습니다.

### 3) 병실 좌표 및 식별자 처리 문제
Canvas 병실 배치도에서 좌표 계산이 어긋나거나, MongoDB 식별자와 클라이언트 문자열 처리 방식이 맞지 않아 조회가 실패하는 문제가 있었습니다.  
병실 번호 파싱 로직과 식별자 처리 방식을 다시 정리해 화면 표시와 조회 흐름을 맞췄습니다.

### 4) 외부 문자 발송 기능 연동 한계
문자 알림 기능은 별도 테스트 수준에서는 확인했지만, 메인 서비스에 안정적으로 통합하지는 못했습니다.  
이 경험을 통해 외부 통신 기능은 핵심 서비스 로직과 분리해 설계하는 것이 중요하다는 점을 배웠습니다.

## 8. 회고

이 프로젝트를 통해 단순한 CRUD 구현을 넘어,  
사용자 역할에 따라 처리 흐름이 달라지는 웹 시스템을 설계하고 구현하는 경험을 할 수 있었습니다.

특히 팀장으로서 기능을 나누는 것만큼 중요한 것이  
초기 구조와 인터페이스를 맞추고, 마지막에 전체 코드를 통합 가능한 상태로 정리하는 과정이라는 점을 크게 느꼈습니다.

돌아보면 렌더링 방식 통일, 입력/응답 형식 표준화, 외부 API 분리 설계를 더 일찍 정리했다면  
프로젝트 구조를 더 안정적으로 가져갈 수 있었을 것이라고 생각합니다.
